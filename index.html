Curriculum Vitae

Cemal Melih Tanış is working as a research engineer in the group of Satellite Services and Research of Arctic Space Centre of Finnish Meteorological Institute (FMI). He has completed his master’s programme in Aalto University in 2020 and he has a scientific and engineering background in electronics, nanotechnology and space technology. He has over 12 years of professional experience in remote sensing of snow and vegetation, research, product development, maintenance and validation, software development, web development, user uptake and networking activities, in different national and international projects and actions. He is interested in innovative solutions and futuristic concepts not only in his own expertise but in every field of science and every part of life.

Finnish Meteorological Institute
Research Engineer, October 2013 -

Remote sensing of snow cover and vegetation, webcam data, satellite data, geospatial data, multispectral sensor data, radiometer data, software development, processing chains, fullstack development, CI/CD, web development, exploitation.
My main responsibilities in the “Satellite Research and Services” group in the “Arctic Research Centre” in FMI are determined on a project- and service-need basis. In the last decade, I had have experience in full-stack development, maintenance, validation and documentation of processing chains for remote sensing and model-based hydrological and climatological products, service and project management, software and web development, and capacity building/assessment of essential climate variables. Our thematic area was mainly snow and ice, although I also got involved in vegetation. During the implementation of such activities, I have used data from active and passive space-born sensors and level 2, 3, and 4 derivations of those, webcam imagery, automatic weather station measurements, meteorological reanalysis and forecast data, hydrological model outputs and, static raster and vector data. Our services use, produce, and disseminate the data and products mostly in a near real-time fashion, which requires to use of APIs and other interfaces efficiently. On the outreach side, I have published my scientific results in peer-reviewed (open access) journals, conferences and workshops, organized workshops, webinars and demo sessions, and participated in one of the COST actions. I also developed an image processing tool (FMIPROT) for webcam imagery to produce environmental data, including but not limited to snow and vegetation, and a demo service using it to produce such data in NRT fashion.

Tasks:

    • Programming

    Python has been my primary programming language since 2014. Generally, I script processing routines and algorithm applications for geospatial data. I handle C, C++ and MATLAB when needed, these cases usually being fixes and debugging in legacy code, or if some calculation is not efficient enough in Python. When creating web applications and APIs, I also use PHP and JS.
    For operational applications, I use Linux systems, jobs scheduling and scripting, remote development and version control.

    GIS

    I use QGIS, SNAP and Panoply to visualize and process vector and raster data. Different formats of those data include Geotiff, netCDF, ESRI Shapefile, geopackage, Sentinel data, etc. Using the web tool described in “Web2,” I can also visualize geospatial data in web pages and web applications.

    3D Graphics

    I have experience in 3D graphics through my webcam data processing research, where I have used VTK to simulate and visualize how the webcam view of the field of view is formed. I am also currently working on the side, on NVIDIA Omniverse to investigate how it can be used similarly, either for webcam or satellite sensors.

    Web2

    I use different web tools and programming languages to build and maintain project websites, portals and web applications. These are generally not the product itself but a deliverable of a larger project or product. Thus, how much of a tool I am using, how well the time and importance limitations restrict the design, and which tool my company provides by default. That said, I can adapt and learn any relevant tools for the purpose.
    I use HTML, CSS, JS and Bootstrap for frontend and PHP, and JS for backend. For geospatial applications, I often use Leaflet and dygraphs to plot data.

    Mobile

    I use FlutterFlow to develop mobile applications which are not very complex but can use Firebase authentication and database, Firestore cloud storage and external APIs.

    Cloud-native, containerization, HPC

    I develop dockerized, cloud-native applications which use cloud object storage and external APIs, for example, satellite data processing routines to be deployed in larger cloud processing systems.
    I use SLURM to manage running parallel processes in HPCs.

    Project management

    I have experience in project management by assisting project managers for multiple years and also managing my company’s progress and responsibilities in an international, multi-million Euro project. I use Microsoft Office 365 tools, such as Planner, or JIRA.
